Follow the user-level `sdd` Skill. Work only on Phase III: design and implementation planning. Map accepted requirements to design decisions, rationale, and verification methods with expected results. Divide implementation into actionable work items with scope, exclusions, acceptance conditions, verification, dependencies, and affected unresolved decisions. Work items may be planned as GitHub Issues when that tracking system is used; do not create Issues or PRs. Do not prescribe commits before implementation. Do not write code or project files. Assess whether an implementing agent can perform each unblocked item without inventing product behavior, then present unresolved decisions and affected work.
